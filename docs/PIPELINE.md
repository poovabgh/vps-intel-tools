# 日更流水线：混合方案（推荐）

本文固定长期设计。实现脚本可分阶段补齐；语义不要轻易改。

## 两种原始方案对比

### A — 官方 RSS 持续抓 + BJT 定点处理

- 发现：只靠官方 RSS。
- 处理：北京时间 08 / 12 / 16 / 20 / 00，按「上一关闭窗」深读（例如 12 点处理 00–08 发现的帖）。

**优点**：处理节奏清晰；窗末到处理相隔约 4h，跟帖更成熟。  
**缺点**：RSS 大约只滚 **20** 条；任务宕机、发帖突发 >20 都会漏；不能翻历史补洞。

### B — 同钟点、TG 从游标拉到最新 → 立刻深读入库

- 发现：电报频道增量（成熟、可 `?before=`）。
- 处理：筛完关键词马上深读+写 vps-intel。

**优点**：发现面完整。  
**缺点**：新帖常 **0 回复**；立刻深读证据薄、浪费配额；和「等评论停一停」的观察相反。

## 推荐：Hybrid（A 的时钟 + B 的发现，且延迟深读）

| 阶段 | 做什么 | 不做 |
|------|--------|------|
| **Discover**（每 15–30min 或每小时） | TG 增量（主）+ 可选 RSS（辅）→ 关键词分类 → 写入 `queue/`（`discovered_at`, keep, brand_tier） | 深读、写 evidence |
| **Process**（BJT 08/12/16/20/00） | 取「上一关闭发现窗」内、且已届成熟的 keep → 论坛首页深读 | 不拿刚发现的热帖硬读 |
| **Ingest** | 高信号（NQ/TQ/线路/风险）可直接 commit 到 vps-intel；纯收售/券 → 核对表或带时间窗的 soft-ingest | 养号回复仍人工审批 |

### 为什么长期更稳

1. **发现不怕漏**：TG 历史游标是主通路；RSS 只补「此刻最新」。
2. **证据质量**：窗末→处理隔约 4h，跟帖大体停稳再读。
3. **职责清晰**：本仓 = 脚本/词库/队列/状态；[vps-intel](https://github.com/poovabgh/vps-intel) = 文档与证据。
4. **可恢复**：`last_tg_msg_id`、`processed_post_ids`、`failed_404` 可重跑；不依赖 RSS 那 20 条还在不在。
5. **可调闸门**：大促可临时放宽「高信号自动入库」；日常仍可对收售保留核对。

## BJT 处理槽 ↔ 发现窗（务必按此表）

| BJT 执行 | 处理「discovered_at」落在的区间 | 处理时帖龄大约 |
|----------|----------------------------------|----------------|
| **12:00** | **00:00–08:00** | 4–12 h |
| **16:00** | **08:00–12:00** | 4–8 h |
| **20:00** | **12:00–16:00** | 4–8 h |
| **00:00** | **16:00–20:00** | 4–8 h |
| **08:00** | **20:00–00:00**（跨日） | 4–12 h |

规律：每个发现窗在 **结束后再等一个 4h 槽** 才被处理（08 窗结束于 08:00，于 12:00 处理）。

## 状态与产物

```
vps-intel-tools/
  state/          # gitignore：游标、已处理、404 重试
  queue/          # gitignore：待深读队列（CSV/JSONL）
  tools/…         # 采集与分类脚本、keywords.yml
vps-intel/
  brands/ docs/   # 唯一证据归属
```

## 入库策略（Process 阶段）

- **高信号**（实测/NQ/TQ/线路/跑路风险等）：深读后可自动写入对应 brand evidence + 推送。
- **收售 / 优惠券 / 弱讨论**：写入当日核对或归档 md，带 `time_window`；通用品牌不进重点观测混排。
- **404**：记入 `failed_404`，下几槽重试，不堵主队列。

## 与仓库边界

| 仓库 | 内容 |
|------|------|
| **poovabgh/vps-intel-tools**（本仓） | fetch / classify / 未来 RSS / 队列处理 / 词库版本 / 日程说明 |
| **poovabgh/vps-intel** | brands、evidence、learning、brands-priority / brands-general |
| **qiaoen12/vps-watchlist** | 关注/速度表；**不**承担本流水线 |

名单权威在 vps-intel 的 `docs/brands-*.md`；本仓 `keywords.yml` 与之对齐，变更时两边都要更新说明。
