# 日更流水线（现行约定）

发现与筛选：**脚本 + 官方 RSS**，不耗模型。  
分析与入库：**到点的 AI** 只读已关闭时段文件。

## 为什么用「5 分钟 RSS → 时段文件」

官方 RSS 单次大约只有最新 ~20 条。**只要采集进程一直在跑**，每隔 5 分钟拉一次并按 `post_id` 去重写入当前时段文件，则 5 分钟内几乎不可能冒出超过 20 条新帖，发现面足够日常使用。

相对电报增量：实现更简单、AI 完全不用碰采集工具；代价是采集宕机超过「RSS 窗口能覆盖的时长」时可能漏帖（可另加电报补洞，非必须）。

## 发现（勤、轻）— 纯脚本

| 项 | 约定 |
|----|------|
| 源 | `https://rss.nodeseek.com/` |
| 频率 | 每 **5 分钟** 一轮 |
| 动作 | 拉 RSS → 与已见 `post_id` 去重 → **关键词筛选** → 追加进**当前 BJT 时段文件** |
| AI | **不参与** |

### 时段文件命名（北京时间）

格式：`YYYYMMDDHHmm` = 窗起点 + 窗终点（时刻用四位）。

| BJT 发现窗 | 文件名示例（2026-10-13） |
|------------|--------------------------|
| 00:00–08:00 | `202610130008.csv` |
| 08:00–12:00 | `202610130812.csv` |
| 12:00–16:00 | `202610131216.csv` |
| 16:00–20:00 | `202610131620.csv` |
| 20:00–00:00 | `202610132000.csv`（跨日：终点为次日 00，也可用 `202610132000_次日`；实现时固定一种） |

建议路径：`queue/buckets/`（gitignore）。  
文件内只保留筛选后的行：链接、标题、发现时间、命中词、品牌标签等——**去掉冗余正文**，保持小文件。

本地同时大约只有：

1. **正在写的**当前窗文件  
2. **已关闭、等 AI 读的**上一窗（或两窗）  
3. 可选：处理中临时副本  

分析入库完成后 **删除** 对应原始桶文件，不堆历史。

## 处理（到点）— AI 只读文件

| BJT 启动 | 读取并分析的文件 | 窗已关闭多久 |
|----------|------------------|--------------|
| **12:00** | `…0008`（00–08） | ≥ 4 h |
| **16:00** | `…0812`（08–12） | ≥ 4 h |
| **20:00** | `…1216`（12–16） | ≥ 4 h |
| **00:00** | `…1620`（16–20） | ≥ 4 h |
| **08:00** | `…2000`（20–00） | ≥ 4 h |

流程：读桶 → **三层漏斗深读**（见 [FUNNEL.md](FUNNEL.md)，**跨渠道框架**）→ 写入 [vps-intel](https://github.com/poovabgh/vps-intel) → 推送 → **删桶文件**。  
固定四方向：长期三（线路机 / IP质量 / 建站机）+ 短期一（优惠推广抢购交易溢价）。`channel=nodeseek|lowendtalk` 只改发现与 `raw/<channel>/`，主题同一套。 短期优惠排查对照 intel [`mother-chicken-watch-2026-10.md`](https://github.com/poovabgh/vps-intel/blob/main/docs/learning/short-term/mother-chicken-watch-2026-10.md)（命中品牌/产品线优先记时间窗）。  
- **L1**：服务器相关，默认第 1 页，短证据可入库。  
- **L2**：命中**长期三话题**才升档——线路机（回程/CN2/软银/IX…）/ IP质量（解锁/AI/TikTok/社媒…）/ 建站机（YABS/超售/并发/IO…）。  
- **L3**：正文/评论信息密度高时才多页（最多 3 页）并保存 HTML 到 `raw/<channel>/<id>/`（本槽为 NodeSeek → `raw/nodeseek/`）；纯收售/优惠默认不上 L3。  
例程细则：[ROUTINE_DEEP_INGEST.md](ROUTINE_DEEP_INGEST.md)。  
LowEndTalk 为另一渠道、同一四方向：[LOWENDTALK.md](LOWENDTALK.md)。

## 职责边界

| 谁 | 做什么 |
|----|--------|
| `vps-intel-tools` 脚本 | RSS 轮询、去重、关键词筛、写/切时段文件 |
| AI（本 bot 例程） | 到点读指定桶文件、深读、入库；**不管** RSS 采集本身 |
| `vps-intel` | 唯一证据与文档归属 |

## 仍建议保留的兜底（可选，后期）

- `seen_post_ids` 小状态文件，防跨窗重复。  
- 采集心跳：若 5 分钟任务停 >30–60 分钟告警（此时才可能撞上 RSS 窗口丢失）。  
- 大促日若怀疑漏帖，再用电报 `?before=` 补洞——日常不必开。

## 消耗统计（SUMMARY 必填）

每轮深读入库结束后，在核对目录 `SUMMARY.md` 写一节 **「消耗统计」**，字段固定：

| 字段 | 含义 |
|------|------|
| 队列条数 | 本桶 keep 行数 |
| 主证据入库 | 实际写入 vps-intel 的主证据条数 |
| 抓回 HTML 总体积 | `raw/` 下文件字节合计 |
| 解析产物 `_parsed.json` | 解析后体积 |
| 脚本墙钟 | 从写出 `queue.csv` 到写出 `SUMMARY.md` 的秒数 |
| 平台 token / 额度 | 填 **未接入**（当前无按次 API；账户总览仅人工看 Usage 设置页） |
| funnel L1 / L2 / L3 | 本轮漏斗计数 |
| 多页抓取帖数 | 抓了 ≥2 页的帖数 |
| 仓库 raw 归档字节 | `vps-intel/raw/nodeseek/` 本轮新增合计 |

说明：RSS 采集脚本不耗模型；上表是「深读这一轮」的代理成本指标，用来横向对比各档负载，**不是**账单金额。若将来平台提供按次用量接口，再把真实 token 填进同一栏。
